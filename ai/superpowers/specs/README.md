# Specs

The archive of specs: how the framework or Shelf should behave, as seen from outside. For the framework:
the public API of a module, a directive or a component feature, with short usage examples and the edge
cases. For Shelf: what a screen shows, its loading, empty and error states, keyboard and screen reader
behavior. A file is `<YYYY-MM-DD>-<slug>.md`, with the slug of the branch `my-<n>-<slug>`. A spec is
written when a task changes observable behavior and committed with the plan, in one commit, before any
code (`ai/workflow.md`, step 5). Read only the spec of the feature you change.
